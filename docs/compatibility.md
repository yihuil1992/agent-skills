# Compatibility

## Skill Shape

`skills/` is the source of truth. `dist/` is generated by the build scripts and provides ready-to-copy layouts for common harnesses.

Each skill is a directory containing:

```text
SKILL.md
references/   optional
scripts/      optional
agents/       optional agent-specific metadata
```

`SKILL.md` is the portable core. Other files are loaded or executed only when the agent chooses to use them.

## Codex / Generic Agents

Install from:

```text
dist/agents/.agents/skills/<skill-name>/
```

Common user-wide destination:

```text
~/.agents/skills/<skill-name>/
```

Some Codex installations also support `~/.codex/skills/<skill-name>/`. Codex can use `agents/openai.yaml` for UI metadata. The skill still works if that file is absent.

## Claude Code

Install from:

```text
dist/claude/.claude/skills/<skill-name>/
```

Common user-wide destination:

```text
~/.claude/skills/<skill-name>/
```

Claude Code primarily needs `SKILL.md` and support files. It can ignore `agents/openai.yaml`.

## Other Agents

GitHub Copilot agent skills can use `dist/github/.github/skills/<skill-name>/`.

Other agents can use the folders in `skills/` or `dist/agents/.agents/skills/` if they support a `SKILL.md`-style instruction bundle, or they can read the folder directly as local instructions.

## Portability Rules

- Keep `SKILL.md` platform-neutral.
- Keep agent-specific metadata optional.
- Avoid absolute user paths.
- Provide PowerShell and Bash entrypoints when automation is expected on Windows, macOS, and Linux.
- Prefer scripts that run from the skill directory or accept explicit paths.
- Document external CLI dependencies inside the skill.
- Rebuild `dist/` from `skills/`; do not hand-edit generated provider copies.
